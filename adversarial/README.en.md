## The concepts (to master)

### Adversarial evasion (adversarial examples)

An **adversarial example** is an input modified in an **imperceptible** way
(noise of a few thousandths) that makes the model wrong with high confidence.

```
original image           noise (×10 magnified)        attacked image
    +-----+                   +-----+                   +-----+
    | 'a' |       +    ε·sign(∇)  |     |       =        | 'h' |  (identical to the eye)
    `-----+                   `-----+                   `-----+
```

### FGSM — Fast Gradient Sign Method (Goodfellow, 2014)

The founding attack. A single step:

```
x_adv = x + ε · sign(∇_x L(f(x), y))
```

- `∇_x L` : gradient of the loss **with respect to the input** (what my backward returns)
- `sign()` : we keep only the direction (+1/-1 per pixel)
- `ε` (epsilon) : the amplitude of the noise — the larger it is, the stronger (and more visible) the attack
- `x_adv = clip(x_adv, 0, 1)` : we stay inside the valid image space

**Why it works:** the model is piecewise linear; a very small push in the
gradient direction accumulates effects across all dimensions and flips the
output. This is Goodfellow's "high-dimensional linearity".

### PGD — Projected Gradient Descent (Madry, 2018) OK implemented

Iterative version of FGSM: several small steps with projection inside the
L∞ ball of radius ε. Stronger attack (the "gold standard" of attacks).

```
x_0 = x + U(-ε, ε)                       # random start
x_{t+1} = clip(x_t + α·sign(∇L), x-ε, x+ε)  # projected gradient step
```

### Attack transfer OK implemented

An adversarial example generated against MY model also fools other models.
This is what makes attacks dangerous in practice (black-box attacks).
Measured on 3 MNIST models trained differently (full, classic, max_config).

### The defence: adversarial training OK implemented

Retraining the model **with** adversarial examples -> it becomes robust.
This is the defensive counterpart — essential to tell both sides.

### Attack transfer — MNIST (FGSM, 500 images)

Transfer rate = images where the TARGET changes prediction, among those the
source fooled and the target predicted correctly.

| Source -> Target | ε=0.10 | ε=0.20 | ε=0.30 |
|---|---|---|---|
| full -> classic (same architecture) | 25.7% | 50.0% | 72.3% |
| full -> max_config (Dropout+L2) | 8.2% | 15.1% | 50.2% |
| max_config -> full | 8.0% | 31.8% | 60.7% |

> **Transferability depends on how similar the models are**: two SGD models
> trained the same way -> the adversarial examples go through (72% at ε=0.3).
> This is what makes **black-box** attacks possible. Regularisation
> (Dropout + L2) breaks part of the transfer.
>
> [warn] **Careful when reading the rate**: it is measured *among the images where
> the SOURCE was fooled*. max_config being harder to fool, its raw rate
> looks higher (31.8% against 15.1% at ε=0.20) without the simple model being
> better protected. The figure that matters on the defence side is the **absolute**
> accuracy of the target: `full` falls to **40.2%** at ε=0.30 under an attack transferred
> from max_config.

## The hardened version — defending against ALL attacks

The previous attacks (FGSM, PGD, targeted, transfer) all exploit the
same weakness: the model is too linear in the small directions of the
gradient. `harden.py` implements **3 combined layers of defence**:

### Layer 1 — PGD adversarial training (the reference defence)

Instead of attacking each batch with FGSM (1 step, weak), we attack it with
**PGD (7 iterations)** during training. The model therefore learns to resist
the strongest iterative attack — not only its simplified version.
This is the result of Madry et al. 2018: training against the strongest
possible attacker gives the highest possible robustness.

```
x_adv = PGD(modèle_courant, batch, eps=0.3, steps=7)   # strong attack on the fly
entraîne sur [batch ; x_adv]                            # clean + adversarial
```

### Layer 2 — Feature squeezing (input defence, Xu et al. 2018)

Before inference, we **reduce the bit depth** of the pixels (8 bits -> 3-4
bits). An adversarial perturbation is a tiny gap on each pixel:
the quantisation crushes it. The useful image stays readable (the model does not
need 256 grey levels), but the adversarial noise disappears.

```
x_entrée = round(x * 7) / 7   # 3 bits: 8 grey levels
```

This is a defence **without retraining**, complementary: it also protects
models already deployed.

### Layer 3 — Multi-attack evaluation (the proof)

A defence that only holds against FGSM is not a defence. `harden.py`
evaluates the hardened model against **all** the attacks in the folder:

- FGSM untargeted
- PGD untargeted (20 steps, random start)
- FGSM targeted (force class 3)
- PGD targeted (force class 3)
- Transfer: attack generated on the standard model -> tested on the hardened one

### Running the hardened version

```bash
# Full training + evaluation (PGD adversarial training, ~30-60 min)
python3 adversarial/scripts/harden.py --n-train 5000 --epochs 3

# FGSM adversarial training (faster, less robust)
python3 adversarial/scripts/harden.py --attack fgsm --n-train 5000 --epochs 3

# Evaluate an already hardened model without retraining
python3 adversarial/scripts/harden.py --load models/defend_pgd_mnist_weights.npz

# Add feature squeezing to the evaluation
python3 adversarial/scripts/harden.py --load models/defend_pgd_mnist_weights.npz --squeeze 3
```

Hardened model weights: `models/defend_pgd_mnist_weights.npz`.

### Hardened version v2 (`harden2.py`) - pushing the frontier

v1 plateaus at 67% clean / 24% under FGSM ε=0.3: it is a budget problem
(5000 images, 3 epochs, random start), not a method problem. v2 starts from the
98.6% clean model, uses the 60000 images, decays the learning rate, clips
the gradients and selects the model on its real robustness.

```bash
# Recommended recipe (automatic warm start on the clean model)
python3 adversarial/scripts/harden2.py --n-train 60000 --epochs 15 --pgd-steps 5

# TRADES: best accuracy/robustness frontier (Zhang et al. 2019)
python3 adversarial/scripts/harden2.py --n-train 60000 --epochs 15 --loss trades

# Fast-AT: much faster, lower robustness (Wong et al. 2020)
python3 adversarial/scripts/harden2.py --n-train 60000 --epochs 15 --attack fgsm-rs

# Honest evaluation of a saved model (PGD 20 steps, 3 restarts, worst case)
python3 adversarial/scripts/harden2.py --report models/harden2_best.npz --restarts 3

# Check that everything runs before launching a long run
python3 adversarial/scripts/harden2.py --quick
```

Each epoch displays the clean accuracy **and** the robustness on a
validation set, with the estimated remaining time. The levers are detailed in
[`defenses.md`](defenses.md) section 6.

## The complete campaign: 3 recipes, a single variable (2026-09-10)

`campagne.sh` answers a precise question: **is it the dataset or the method
that matters?** Three identical runs, except on one point each.

| | Recipe | Clean | FGSM ε=0.30 | PGD ε=0.30 |
|---|---|---|---|---|
| **A** | reference (60000 img, PGD-5, no augmentation) | **98.8%** | **88.2%** | **65.4%** |
| **B** | A + data augmentation | 99.5% | 54.8% | 29.8% |
| **C** | B + TRADES (β=2) | 96.9% | 23.4% | 2.2% |

```bash
./campagne.sh              # NumPy (harden2.py)
./campagne.sh --torch      # PyTorch (harden_torch.py)
./campagne.sh --rapide     # short version, to check the pipeline
./campagne.sh --liste      # show only the planned runs
```

**Run A wins everywhere, by a wide margin.** Against v1: **+31.6 pts of clean
accuracy** and from +64.4 pts (FGSM) to +76.2 pts (PGD) at ε=0.30.

**Augmentation HURT (run B).** Counter-intuitive, but explained by the loss:
it stays stuck at **~0.82** while that of run A goes down to **0.24**. The
augmented model is **under-trained** — each epoch is harder (images already
distorted), so at equal epoch budget it falls behind. It gains in
clean accuracy (99.5% against 98.8%) but loses **35 pts** of robustness at
ε=0.3. Conclusion: augmentation only pays off with **2-3x more epochs**,
and it **does not replace** adversarial training.

**TRADES still needs another go (run C)**: `--lr 0.002` was far too low (the
loss stays frozen at ~1.68) and the lr decay at epochs 5 and 8 finished
freezing the model. To redo with `--lr 0.01` and without aggressive decay.

**A ceiling identified**: the validation robustness of run A plateaus at ~70%
from epoch 5 (26.3 -> 36.7 -> 55.3 -> 64.5 -> 68.5 -> 69.2 -> 70.1 -> 70.1 ->
70.7 -> 70.3). The limiting factor is no longer the recipe, it is the **epoch
budget**.

## Adaptive attacks: BPDA + EOT (2026-09-11)

The hardened model holds 65-67% under PGD -- but PGD is exactly the attack it
was trained against. To know whether the defence is **real**, it must be tested
with an attacker that knows about it. That is the "gradient masking" test
(Athalye, Carlini & Wagner, 2018).

`bpda_eot.py` attacks the model **as it would be deployed** (hardened weights +
feature squeezing at inference) with four attackers:

- **without defence**: PGD on the raw model, ignoring the squeezing (squeezing
  is applied at evaluation time only);
- **naive**: PGD propagates through the quantisation with its **true** Jacobian.
  Rounding is a step function: its derivative is zero almost everywhere (exactly
  what `torch.round` does). The gradient that comes back to the input is zero,
  so the attack does not move a single pixel;
- **BPDA**: exact forward pass, backward pass approximated by the identity;
- **BPDA + EOT**: BPDA with the gradient averaged over random transformations
  (bit depth drawn from {2, 3, 4}, translation +/-2 px).

Result (200 images, PGD-20, squeezing 3 bits, clean accuracy 67.0%):

| eps | without defence | naive (true Jacobian) | BPDA | BPDA + EOT |
|---|---|---|---|---|
| 0.10 | 27.5% | **68.0%** | 27.0% | 41.0% |
| 0.20 | 22.5% | **66.5%** | 21.5% | 37.0% |
| 0.30 | 1.0% | **62.5%** | 1.5% | 10.0% |

```bash
# Hardened v1 model + 3-bit feature squeezing (default)
python3 adversarial/scripts/bpda_eot.py

# More EOT draws, other eps values
python3 adversarial/scripts/bpda_eot.py --bits 3 --eot 8 --eps 0.2 0.3

# Quick pipeline check
python3 adversarial/scripts/bpda_eot.py --quick
```

> **Verdict: the v1 defence was gradient masking.** The naive attacker leaves
> 62.5% to the model at eps=0.30 -- it *looks* solid. BPDA brings it down to
> **1.5%**, the level of an undefended model. The feature squeezing layer
> therefore provided **no real protection**: it merely made the gradient
> unusable for the attacker.
>
> Honest note: BPDA+EOT is here *less* effective than BPDA alone (10.0% vs 1.5%
> at eps=0.30), because the EOT average dilutes the signal at a fixed number of
> steps. The lesson stands: a stochastic defence does not protect, it only makes
> the attack more expensive.

**What this means for the rest of the folder**: the hardened model from the
torch path (98.8% / 65.4%) **does not include** feature squeezing and is not
stochastic. Adaptive attacks therefore apply to it differently, and its real
test comes later: CW (soon) and AutoAttack.

## The PyTorch path — when the model grows

The `adversarial/scripts/` folder contains the **hand-made** implementation:
every gradient is written by hand (`Conv2D.backward`, `col2im`, the routing of the
gradient in the MaxPool...). It is the pedagogical reference of the project, and it
does not move.

But it is **at the ceiling of its BLAS**: measured at 172 img/s on an i5-6300U,
with a time dominated by the matrix products themselves. Doubling the size of the
model doubles the training time, and the GPU is not accessible from NumPy.

`adversarial/torch/` replays **exactly the same experiments** with PyTorch:

- same architecture (421 642 parameters), same attack formulas,
  same recipes (`pgdat`, `trades`, augmentation, warm start, gradient
  clipping, selection on robustness);
- the weights are **interchangeable** (`.npz` format in both directions);
- about **9x faster on CPU**, and usable on GPU.

```bash
# Check equivalence with the hand-made version (run this first)
python3 adversarial/torch/harden_torch.py --parite

# Same campaign as in NumPy, but faster
python3 adversarial/torch/harden_torch.py --n-train 60000 --epochs 15 --pgd-steps 5 --augment
```

Parity test result (200 images, same weights): clean accuracy
**98.50 %** in both implementations, FGSM ε=0.3 **1.50 %** in both,
PGD ε=0.2 **0.00 %** in both.

The complete campaign was launched with this engine (60000 images, 10 epochs,
PGD-5, ~1 min per epoch on a separate machine). It is run A of the table
above that produced the reference result (98.8% / 65.4%).

## What's next

The hardened model holds 65.4% under PGD-20 — but PGD is exactly the attack
against which it was trained. As long as we have not tested anything stronger, we do not
know whether it is a **real defence** or **gradient masking** (a defence
that only moves the vulnerability towards unvisited directions).

| Step | Content | Reference |
|---|---|---|
| 1 | **Adaptive attacks**: BPDA + EOT on the hardened model (break the defence) | Athalye et al. 2018; Tramèr et al. 2020 |
| 2 | **Carlini-Wagner (CW)**: the missing reference white-box attack | Carlini & Wagner 2017 |
| 3 | **Black-box**: score-based (ZOO/NES) then decision-based (Boundary/HSJA) | Chen et al. 2017; Brendel & Bethge 2019 |
| 4 | **Certified robustness**: randomized smoothing (guaranteed L2 bound) | Cohen et al. 2019 |

Additional leads noted: transfer with PGD as source, cross-dataset transfer
MNIST -> EMNIST, ensemble attack, AutoAttack / RobustBench,
physical patches, MITRE ATLAS mapping.
